# 人物证据与置信度协议

## 1. 四类事实状态

| 状态 | 含义 | 可否作为人物事实 |
| --- | --- | --- |
| `observed_evidence` | 材料中直接可见的动作、语言、选择、信息使用或状态变化 | 可以，必须带 source ref |
| `creative_inference` | 由多个证据支持的创作解释 | 仅作为解释，必须带置信度和替代解释 |
| `author_decision` | 作者明确决定但正文未必已证明的设定 | 可以进入设计包，持久化前需 review |
| `open_hypothesis` | 尚待场景、文本或作者确认的假设 | 不得当成 accepted fact |

## 2. 置信度

- `high`：多个独立场景或稳定重复模式支持，且替代解释较弱。
- `medium`：有清晰证据，但样本少、状态变化或叙事视角会影响解释。
- `low`：主要依赖间接信号、单场景或类型惯例。

置信度描述证据强度，不描述人物好坏或分析者信心表演。

## 3. 证据单元

每条分析记录至少包含：

| 字段 | 说明 |
| --- | --- |
| `source_ref` | 文件、章节、场景、段落或用户说明 |
| `observed` | 发生了什么，不解释原因 |
| `facet_or_dimension` | 对应开放本体 facet 或兼容维度 alias |
| `state` | 四类事实状态之一 |
| `interpretation` | 创作解释 |
| `confidence` | high / medium / low |
| `alternatives` | 至少一个可行替代解释 |
| `validation` | 需要什么场景或材料验证 |

## 4. 分析顺序

1. 先记录行为与语言，不写性格词。
2. 查找重复、缺席、转折和关系差异。
3. 将证据映射到能解释当前选择的最小充分 facet 集；数量不是完成标准。
4. 合并支持同一解释的证据；冲突证据单独保留。
5. 给出解释、替代解释、置信度和验证场景。
6. 最后才形成自然语言画像。

## 5. 冲突证据分类

当同一人物表现相反时，按以下顺序检查：

- `state_change`：时间、伤病、资源或情绪状态改变。
- `relationship_specific`：面对不同对象采用不同策略。
- `mask_or_deception`：公开面具、秘密或故意表演。
- `arc_progression`：人物已发生有证据的成长或堕落。
- `viewpoint_bias`：叙事视角或证词不可靠。
- `continuity_error`：缺少铺垫且无法由以上原因解释。

不要把矛盾自动平均为“复杂”。复杂人物仍需可追溯机制。

## 6. 现实人物边界

- 可以描述公开或用户提供文本中的可观察表达方式与决策模式。
- 不诊断精神疾病、人格障碍、暴力风险或说谎概率。
- 不把少量对话当完整人格。
- 涉及真实创伤、自伤或临床风险时，明确这不是专业评估并建议寻求合格专业支持。

## 7. 版权边界

- 优先分析用户提供文本、公开领域材料或短证据片段。
- 对受版权保护作品使用概括和极短证据，不重现大段原文。
- 来源不清或许可证不明的外部 skill 只记录抽象方法，不复制正文。
